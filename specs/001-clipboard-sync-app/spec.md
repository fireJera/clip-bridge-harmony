# Feature Specification: Clip Bridge - 剪贴板管理与多端同步

**Feature Branch**: `001-clipboard-sync-app`
**Created**: 2026-04-05
**Updated**: 2026-04-09 (基于 Figma 设计稿更新 UI 规格)
**Status**: Draft
**Design Reference**: [Figma - Jeremy Ren's team library](https://www.figma.com/design/4gK8iMkmqYLAUxl11W1QEO/Jeremy-Ren-s-team-library)
**Input**: User description: "开发一个鸿蒙原生应用，主要功能保存剪切板历史，多端同步，用户登录"

## Clarifications

### Session 2026-04-05

- Q: Which user stories are in v1.0 release scope? → A: P1+P2 only (clipboard history + search/manage + login); distributed sync (P3) and cloud sync (P4) deferred to v2.
- Q: 点击历史条目时的交互行为？ → A: Tap → 进入详情页（预览完整内容 + 复制按钮 + 置顶/删除操作）。
- Q: 超大内容（>1MB 文本或 >10MB 图片）的处理策略？ → A: 跳过不保存，发送通知提示用户"内容过大，未记录"。
- Q: v1 是否包含用户登录功能？ → A: v1 不包含登录，应用完全本地化，登录注册及同步全部推迟到 v2。
- Q: 去重策略——仅短时间连续去重还是全局去重？ → A: 全局去重，重复内容不新增条目，将已有条目移到列表顶部并更新时间戳。
- Q: v1 新增功能？ → A: 加入自动分类（按内容类型）、自定义分类（用户创建）、收藏功能，均纳入 v1 范围。

### Session 2026-04-09

- Q: Figma 设计稿中的 BottomNavBar 4 Tab 布局（历史/收藏/设备/设置）是否为 v1 布局？ → A: 是，设备管理在 v1 仅展示占位页面，v2 实现同步功能。
- Q: 设计稿中的多种卡片类型（Email、银行卡、链接、电话、地址、文本、图片、代码），是否全部在 v1 支持？ → A: v1 支持文本、链接、邮箱、电话、地址、图片卡片样式，银行卡和代码类型延后。
- Q: HarmonyOS 优化版和通用版以哪个为准？ → A: HarmonyOS 优化版为准，采用圆角卡片、HarmonyOS 风格的 Toggle 开关和导航栏。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自动记录剪贴板历史 (Priority: P1)

用户在日常使用手机时，每次复制文本、图片或链接，应用在后台自动捕获并保存到本地
历史列表中。用户打开应用后，可以看到按时间倒序排列的完整剪贴板历史，包含内容预览、
来源应用、时间戳。点击任意条目可查看完整内容并一键重新复制到剪贴板。

**Why this priority**: 这是应用的核心价值——没有剪贴板历史记录，其他所有功能都无法
展开。这是 MVP 的最小可用切片。

**Independent Test**: 可以通过手动复制多条内容（文本、链接、图片）后打开应用验证
历史列表是否完整记录来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户已安装应用并授予剪贴板权限, **When** 用户在任意应用中复制一段文本,
   **Then** 该文本在 2 秒内出现在剪贴板历史列表顶部
2. **Given** 用户连续复制 3 段不同内容, **When** 用户打开 Clip Bridge 应用,
   **Then** 历史列表显示 3 条记录，按复制时间倒序排列，每条显示内容预览和时间戳
3. **Given** 用户之前复制过某段文本（已在历史列表中）, **When** 用户再次复制相同
   内容, **Then** 不新增条目，已有条目移至列表顶部并更新时间戳
4. **Given** 历史列表中有条目, **When** 用户点击某条目, **Then** 进入详情页显示
   完整内容，提供"复制"按钮、置顶和删除操作
5. **Given** 用户在相册中复制了一张图片, **When** 用户打开 Clip Bridge 应用,
   **Then** 历史列表中显示该图片的缩略图预览

---

### User Story 2 - 搜索与管理剪贴板历史 (Priority: P2)

用户可以在历史列表中通过关键词搜索特定的剪贴板条目。用户可以删除单条记录、
批量删除、或一键清空全部历史。用户可以置顶重要条目使其不被自动清理。

**Why this priority**: 历史管理是核心体验的必要补充——随着历史条目增长，搜索和管理
功能是保持可用性的关键。但应用在只有 P1 时仍有基础价值。

**Independent Test**: 通过创建多条历史记录后测试搜索、删除、置顶操作来独立验证。

**Acceptance Scenarios**:

1. **Given** 历史列表中有 50+ 条包含"密码"关键词的条目, **When** 用户在搜索框
   输入"密码", **Then** 列表实时过滤仅显示匹配条目
2. **Given** 用户长按某条历史记录, **When** 选择"删除", **Then** 该条目从列表中
   移除且不可恢复
3. **Given** 用户在列表中选择了多条记录, **When** 点击"批量删除", **Then** 所有
   选中的条目被移除
4. **Given** 用户对某条记录执行"置顶"操作, **When** 返回历史列表, **Then** 该
   条目出现在列表最顶部的"置顶"区域，且不会被自动清理
5. **Given** 历史条目达到上限（默认 500 条）, **When** 新条目被捕获, **Then** 最
   旧的未置顶且未收藏的条目被自动移除

---

### User Story 3 - 自动分类与收藏夹 (Priority: P2)

每条剪贴板记录在保存时自动识别内容类型并归类：文本、链接、邮箱、手机号、图片、
地址等。用户可以在历史列表中按类型筛选查看。同时，用户可以创建自定义收藏夹（如
"工作"、"密码"、"常用语"），并将任意条目添加到一个或多个收藏夹中。被加入收藏夹
的条目会出现在独立的"收藏"Tab 页中，用户可在收藏页按收藏夹筛选查看。

**Why this priority**: 收藏夹是管理大量历史记录的核心能力，与搜索功能互为补充。
有了收藏夹，用户可以在数百条记录中快速定位目标内容。与 P2 的搜索/管理功能同等重要。

**Independent Test**: 复制不同类型的内容（邮箱、链接、电话、纯文本、图片）后验证
自动分类是否正确；创建收藏夹并给条目加入收藏夹后按收藏夹筛选。

**Acceptance Scenarios**:

1. **Given** 用户复制了一个邮箱地址, **When** 条目出现在历史列表中, **Then** 该条目
   自动标记为"邮箱"类型，在分类筛选中选择"邮箱"可看到该条目
2. **Given** 用户复制了一个手机号, **When** 条目出现在历史列表中, **Then** 该条目
   自动标记为"手机号"类型
3. **Given** 用户复制了一段纯文本（不含邮箱/链接/电话等模式）, **When** 条目出现在
   历史列表中, **Then** 该条目标记为"文本"类型
4. **Given** 历史列表中有多个类型的条目, **When** 用户在分类筛选中选择"链接",
   **Then** 仅显示链接类型的条目
5. **Given** 用户创建了一个名为"工作"的收藏夹, **When** 用户将某条目添加到"工作"
   收藏夹, **Then** 该条目出现在"收藏"Tab 页中，在"工作"收藏夹筛选下可见
6. **Given** 某条目已添加到"工作"和"常用"两个收藏夹, **When** 用户按"工作"或
   "常用"筛选, **Then** 该条目均出现在结果中
7. **Given** 用户删除了一个收藏夹, **When** 删除完成, **Then** 所有条目与该
   收藏夹的关联被移除，条目本身不删除

---

### User Story 4 - 收藏夹管理条目 (Priority: P2)

用户可以在详情页中将条目添加到一个或多个收藏夹。被添加到收藏夹的条目会出现在
独立的"收藏"Tab 页中，用户可在收藏页按收藏夹筛选查看。将条目从所有收藏夹中
移除后，该条目从收藏视图消失但仍在主历史列表中。

**Why this priority**: 收藏夹是管理大量历史记录的核心能力，与搜索功能互为补充。
有了收藏夹，用户可以在数百条记录中快速定位目标内容。与 P2 的搜索/管理功能同等重要。

**Independent Test**: 创建收藏夹后，在详情页将条目添加到收藏夹，验证收藏页中
按收藏夹筛选是否正确工作；移除所有收藏夹关联后验证条目从收藏页消失。

**Acceptance Scenarios**:

1. **Given** 用户已创建收藏夹"工作", **When** 在详情页将某条目添加到"工作"收藏夹,
   **Then** 该条目出现在"收藏"Tab 页中
2. **Given** 收藏页中有多个条目分布在不同收藏夹, **When** 用户在收藏页筛选某个
   收藏夹, **Then** 仅显示属于该收藏夹的条目
3. **Given** 某条目同时属于"工作"和"常用"两个收藏夹, **When** 用户按"工作"或
   "常用"筛选, **Then** 该条目均出现在结果中
4. **Given** 用户将某条目从所有收藏夹中移除, **When** 操作完成, **Then** 该条目
   从收藏视图消失，但在主历史列表中仍然存在
5. **Given** 用户在详情页中, **When** 查看条目详情, **Then** 可看到该条目所属的
   收藏夹列表，并可添加到或移出收藏夹

---

### User Story 5 - 用户注册与登录 (Priority: P3, **v2 scope**)

用户可以通过手机号 + 验证码注册账号并登录。登录后，用户可以开启云同步功能，
在不同设备间同步剪贴板历史。未登录用户仍可使用本地剪贴板历史功能。

**Why this priority**: 用户登录是云同步的前置条件，但本地功能不依赖登录。P2 优先级
确保应用在离线/未登录状态下仍有完整价值。

**Independent Test**: 可以通过注册新账号、登录、退出登录流程来独立测试，无需
依赖同步功能。

**Acceptance Scenarios**:

1. **Given** 用户打开应用首次使用, **When** 选择"手机号登录"并输入有效手机号和
   验证码, **Then** 账号自动创建并登录成功，进入主界面
2. **Given** 用户已注册, **When** 在新设备上使用相同手机号和验证码登录,
   **Then** 登录成功，若已开启云同步则开始拉取云端历史
3. **Given** 用户已登录, **When** 点击"退出登录", **Then** 账号退出，云同步停止，
   本地历史保留不受影响
4. **Given** 用户未登录, **When** 使用应用, **Then** 所有本地功能（剪贴板监听、
   历史查看、搜索、管理）正常可用
5. **Given** 用户已登录, **When** 用户手动触发数据清除, **Then** 提供选项：
   仅清除本地数据 / 仅清除云端数据 / 全部清除，需二次确认

---

### User Story 6 - 鸿蒙设备间近场同步 (Priority: P4, **v2 scope**)

用户在同一个鸿蒙账号下的多台设备之间，剪贴板历史自动通过鸿蒙分布式能力实时同步。
当用户在设备 A 复制内容后，设备 B 的剪贴板历史列表中自动出现该条目。

**Why this priority**: 鸿蒙分布式同步是平台特色功能，但依赖特定硬件生态。在 MVP
阶段本地功能已足够，分布式同步作为差异化体验在 P3 阶段添加。

**Independent Test**: 需要两台鸿蒙设备登录同一账号，在一台设备复制内容后验证
另一台设备的历史列表更新。

**Acceptance Scenarios**:

1. **Given** 用户在设备 A 和设备 B 均登录同一鸿蒙账号, **When** 设备 A 复制一段
   文本, **Then** 设备 B 的剪贴板历史列表在 5 秒内出现该条目
2. **Given** 两台设备正在进行分布式同步, **When** 网络断开, **Then** 各设备本地
   功能不受影响，恢复连接后自动同步差异条目
3. **Given** 用户在设备 A 删除一条同步记录, **When** 同步完成后, **Then** 设备 B
   上该条目也被标记为删除

---

### User Story 7 - 云端多端同步 (Priority: P5, **v2 scope**)

用户开启云同步后，剪贴板历史通过云端服务在不同设备间同步（包括非鸿蒙设备通过
Web 端或其他客户端访问）。支持增量同步和离线冲突处理。

**Why this priority**: 云同步扩展了设备覆盖范围，但实现复杂度较高。在 P3 分布式
同步已提供基础同步能力后，云同步作为扩展功能。

**Independent Test**: 在一台设备上复制内容后，通过云端 API 或另一台设备登录同一
账号验证同步结果。

**Acceptance Scenarios**:

1. **Given** 用户已登录并开启云同步, **When** 在设备 A 复制内容, **Then** 云端
   存储该条目，设备 B 登录后自动拉取
2. **Given** 设备处于离线状态, **When** 用户复制了多条内容, **Then** 恢复网络后
   所有离线条目按时间顺序同步到云端
3. **Given** 两个设备同时修改了同一条目的备注, **When** 同步冲突发生, **Then**
   用户看到冲突提示并选择保留哪个版本
4. **Given** 用户在设置中关闭云同步, **When** 关闭完成, **Then** 本地历史保留但
   不再上传新条目，云端数据不变

---

### Edge Cases

- 当系统剪贴板权限被用户撤销时，应用应提示并引导用户重新授权
- 当设备存储空间不足时，自动清理最旧条目并提示用户
- 当用户在"隐私模式"下暂停监听后复制了密码等敏感内容，恢复监听时不应捕获该内容
- 当鸿蒙分布式同步和云同步同时开启且产生冲突时，以最新时间戳为准，并标记冲突
- 当应用被系统杀死后台后重新启动，通过持久化队列恢复监听，避免遗漏
- 当复制的内容包含超大文本（>1MB）或超大图片（>10MB）时，跳过不保存，通过通知
  提示用户"内容过大，未记录到剪贴板历史"

## UI Design Specification *(based on Figma)*

### 应用导航结构

应用采用 **BottomNavBar** 底部导航栏布局，包含 4 个主 Tab：

| Tab | 图标 | 说明 |
|-----|------|------|
| 历史 (History) | 时钟图标 | 默认 Tab，展示剪贴板历史列表 |
| 收藏 (Favorites) | 星标图标 | 展示收藏的条目列表 |
| 设备 (Devices) | 设备图标 | v1 为占位页，v2 实现设备管理 |
| 设置 (Settings) | 齿轮图标 | 应用设置页面 |

底部导航栏高度 56px（HarmonyOS 版本），选中态高亮当前 Tab 图标和文字。

### Page 1: History 历史页面

**布局结构**（HarmonyOS 优化版，自上而下）：

1. **TopAppBar** (64px)
   - 左侧: 无返回按钮（主页面）
   - 中间: "History" 标题 (H2)
   - 右侧: 用户头像按钮（圆形，34x34）

2. **搜索栏** (53px)
   - 搜索输入框: 圆角容器，左侧搜索图标，占位文本 "Search history..."
   - 输入时实时过滤列表

3. **分类标签**（水平滚动，84px）
   - 第一行 — 内容类型标签: 全部 | 邮箱 | 链接 | 电话 | 地址 | 图片
   - 选中态: 填充背景色，未选中态: 描边样式
   - 标签高度 36px，圆角，支持水平滚动

4. **历史列表区域**
   - 时间分组标签: "Today" / "Yesterday" / 更早（16px 高度，左对齐）
   - 卡片列表: 每种类型有不同的卡片样式

5. **FAB 按钮**（可选，右下角浮动）
   - 圆形按钮（56x56），用于快捷操作

**卡片设计 — 按内容类型区分**：

每种类型的卡片包含三个区域：头部（类型标识）、内容区、底部（标签/操作）

| 卡片类型 | 头部 | 内容区 | 底部标签 |
|----------|------|--------|----------|
| **Text 文本** | 文档图标 + "Text" + 时间 | 文本内容预览（带左边框装饰线），最多 3 行 | 自定义标签（如"工作"、"笔记"） |
| **Link 链接** | 链接图标 + "Link" + 时间 | 链接预览卡片（含小图标 + 网站名 + URL摘要） | "链接" 标签 |
| **Email 邮箱** | 信封图标 + "Email" + 时间 | 邮箱地址（可点击） | "邮箱" 标签 |
| **Phone 电话** | 电话图标 + "Phone" + 时间 | 电话号码（格式化显示） | "电话" 标签 |
| **Address 地址** | 位置图标 + "Address" + 时间 | 地址文本 | "地址" 标签 |
| **Image 图片** | 图片图标 + "Image" + 时间 | 图片缩略图预览（圆角，宽高比自适应） | "图片" 标签 |

**卡片通用结构**：
- 圆角卡片（HarmonyOS 风格大圆角）
- 左右内边距 16px
- 头部: 类型图标（40x40 圆角背景）+ 类型名称（小字灰色）+ 时间（小字灰色）→ 右侧三点菜单按钮
- 内容区: 根据类型展示不同内容预览
- 底部: 自动类型标签 + 自定义标签（圆角胶囊样式）

### Page 2: Clip Detail 详情页

**布局结构**（HarmonyOS 优化版）：

1. **TopAppBar** (64px)
   - 左侧: 返回按钮（箭头图标）
   - 中间: 页面标题
   - 右侧: 收藏按钮（星标图标，可切换）+ 编辑按钮

2. **内容展示区 — Fluid Hub**
   - 圆角容器，展示原始内容（只读模式）
   - 左上角小标签: "Original Snippet"
   - 右下角显示内容类型 + 字符数（如 "Text · 182 chars"）
   - 右侧可选装饰图标

3. **可编辑内容区**
   - 标签: "Edit Content"
   - 圆角容器，内含可编辑文本区域（带内边距）
   - 文本区域可编辑，支持滚动

4. **笔记区**
   - 标签: "Contextual Notes"
   - 圆角容器，内含输入区域

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 应用 MUST 在后台持续监听系统剪贴板变化，自动捕获每次复制操作的内容
- **FR-002**: 应用 MUST 支持捕获以下内容类型：纯文本、链接（识别为 URL 并标记）、
  图片、URI。文本超过 1MB 或图片超过 10MB 时 MUST 跳过不保存并通过系统通知
  告知用户
- **FR-003**: 每条剪贴板记录 MUST 包含：内容、内容类型、来源应用标识（如系统允许）、
  捕获时间戳、是否置顶、同步状态标记
- **FR-004**: 应用 MUST 对所有重复内容进行全局去重。当用户复制与历史中已有条目相同的
  内容时，不新增条目，而是将已有条目移至列表顶部并更新其时间戳
- **FR-005**: 应用 MUST 提供按时间倒序排列的剪贴板历史列表，支持虚拟滚动以处理
  大量条目
- **FR-006**: 点击历史条目 MUST 进入详情页，展示完整内容预览，提供"复制到剪贴板"
  按钮、置顶和删除操作入口
- **FR-007**: 用户 MUST 能通过关键词搜索历史记录（支持文本内容全文搜索）
- **FR-008**: 用户 MUST 能删除单条记录、批量删除、清空全部历史
- **FR-009**: 用户 MUST 能置顶重要条目，置顶条目不被自动清理
- **FR-010**: 历史条目上限 MUST 可配置（默认 500 条），达到上限后自动清理最旧的
  未收藏且未置顶的条目
- **FR-010a**: 应用 MUST 对每条剪贴板记录自动识别内容类型并归类。支持以下自动类型：
  文本（text）、链接（url）、邮箱（email）、手机号（phone）、图片（image）、
  地址（address）
- **FR-010b**: 用户 MUST 能在历史列表中按自动类型筛选条目
- **FR-010c**: 用户 MUST 能创建、重命名、删除收藏夹，收藏夹数量上限为 50 个
- **FR-010d**: 用户 MUST 能为任意剪贴板条目添加到或移出一个或多个收藏夹
- **FR-010e**: 收藏页面 MUST 支持按收藏夹筛选查看条目
- **FR-010f**: 被添加到至少一个收藏夹的条目 MUST 出现在独立的"收藏"Tab 视图中
- **FR-010g**: 属于收藏夹的条目 MUST 不被自动清理（与置顶同级保护）
- **FR-010h**: 用户将条目从所有收藏夹中移除后，该条目 MUST 从收藏视图消失但保留在主历史列表中
- **FR-011**: 应用 MUST 支持手机号 + 短信验证码注册和登录
- **FR-012**: 未登录用户 MUST 能使用全部本地功能（监听、历史、搜索、管理）
- **FR-013**: 登录用户 MUST 能选择是否开启云同步功能（默认关闭）
- **FR-014**: 云同步 MUST 采用增量同步策略，仅传输新增和变更的条目
- **FR-015**: 应用 MUST 在离线状态下正常工作，本地功能不受网络影响
- **FR-016**: 应用 MUST 支持鸿蒙分布式数据同步，在相同鸿蒙账号的设备间实时同步
- **FR-017**: 同步冲突 MUST 提供用户界面让用户选择保留哪个版本
- **FR-018**: 用户 MUST 能暂停剪贴板监听（隐私模式），暂停期间不捕获任何内容
- **FR-019**: 用户 MUST 能按应用设置监听黑名单，黑名单应用的复制不记录
- **FR-020**: 应用 MUST 在从后台恢复时要求生物识别或设备密码验证才能查看历史
- **FR-021**: 所有本地存储的剪贴板内容 MUST 加密存储
- **FR-022**: 用户 MUST 能手动清除本地数据、云端数据或全部数据

### UI Design Requirements (v1 scope, based on Figma HarmonyOS 版本)

- **FR-D01**: 应用 MUST 使用 BottomNavBar 底部导航栏，包含 4 个 Tab: 历史、收藏、设备、设置
- **FR-D02**: 历史列表 MUST 按时间分组显示（Today / Yesterday / 更早），每组带分组标签
- **FR-D03**: 历史列表 MUST 提供水平滚动的分类标签筛选栏（全部/邮箱/链接/电话/地址/图片）
- **FR-D04**: 每种内容类型的卡片 MUST 展示对应类型的图标和内容预览
- **FR-D05**: 卡片 MUST 使用 HarmonyOS 风格的圆角设计，包含头部（类型图标+名称+时间）、内容区、底部标签区三个区域
- **FR-D06**: 详情页 MUST 包含内容展示区（Fluid Hub）、可编辑内容区、笔记区、标签管理区
- **FR-D07**: 详情页底部 MUST 固定显示 "Copy to Clipboard" 操作按钮
- **FR-D08**: 收藏页面 MUST 支持按收藏夹筛选（水平滚动收藏夹标签栏），卡片样式与历史页一致
- **FR-D09**: 设置页面 MUST 包含以下分区: 录制开关、同步开关、关于信息
- **FR-D10**: 设置项 MUST 使用圆角卡片分组，每行含左侧图标 + 标题描述 + 右侧控件
- **FR-D11**: Toggle 开关 MUST 使用 HarmonyOS 风格（圆角滑块设计）
- **FR-D12**: 设备管理页面 v1 MUST 显示占位内容，标明"即将上线"

### Key Entities

- **ClipboardEntry**: 一条剪贴板记录，包含内容、自动类型（text/url/email/phone/
  image/address）、来源应用、捕获时间、是否置顶、是否收藏、同步状态
- **CustomCategory**: 用户自定义收藏夹，包含名称、创建时间、排序序号、关联条目数
- **EntryCategoryRelation**: 条目与收藏夹的多对多关联，包含条目 ID 和收藏夹 ID
- **UserProfile**: 用户账号信息（v2），包含手机号、登录状态、云同步开关、
  上次同步时间戳
- **SyncRecord**: 同步元数据（v2），记录每个条目的同步状态、设备标识、
  同步时间戳，用于冲突检测和增量同步
- **AppBlacklistEntry**: 监听黑名单条目，关联应用包名和应用名称

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 剪贴板内容从复制到出现在历史列表中的延迟不超过 2 秒
- **SC-002**: 历史列表在 500 条记录时滑动流畅，无卡顿（用户感知 60fps）
- **SC-003**: 搜索功能在 500 条记录中返回结果不超过 500 毫秒
- **SC-004**: 应用冷启动到显示历史列表不超过 2 秒
- **SC-005**: 后台监听服务每小时耗电不超过设备总电量的 1%
- **SC-006**: 鸿蒙分布式同步延迟不超过 5 秒（同网络环境下）
- **SC-007**: 90% 的用户能在 3 步内完成"复制→查看→再复制"的核心流程
- **SC-008**: 用户注册登录流程在 60 秒内可完成（假设验证码即时到达）
- **SC-009**: 离线场景下全部本地功能正常，恢复网络后自动完成增量同步
- **SC-010**: 自动类型识别准确率不低于 95%（基于常见邮箱、手机号、URL 格式判断）
- **SC-011**: 按自定义分类筛选在 500 条记录中返回结果不超过 500 毫秒
- **SC-012**: 收藏视图在 100 条收藏条目下加载时间不超过 300 毫秒
- **SC-013**: UI 实现与 Figma 设计稿视觉一致性不低于 90%（按页面对比验证）
- **SC-014**: BottomNavBar Tab 切换响应时间不超过 200 毫秒

## Assumptions

- **v1 范围**: v1.0 交付 User Story 1-4（本地剪贴板历史 + 搜索管理 + 自动分类/
  自定义标签 + 收藏）。用户登录 (US5)、鸿蒙分布式同步 (US6) 和云端多端同步
  (US7) 计划在 v2 中实现。v1 为纯本地应用，无需账号系统。v1 架构必须预留同步
  和用户认证接口但无需实现。
- **v1 UI 范围**: v1 实现 Figma HarmonyOS 优化版中的 History、Clip Detail、
  Favorites、Settings 四个主页面。Devices 页面 v1 仅展示占位内容。
  卡片类型 v1 支持: 文本、链接、邮箱、电话、地址、图片。银行卡和代码类型延后。
- **设计参考**: 以 Figma 设计稿 HarmonyOS 优化版（node 2316:2）为视觉基准，
  通用版（node 0:1）作为补充参考
- 用户设备为 HarmonyOS NEXT (API 12+) 系统，不支持旧版 HarmonyOS 或 Android
- 手机号验证码服务使用第三方短信服务提供商，应用自身不实现短信网关
- 云端后端服务作为独立项目开发，本应用作为客户端通过 API 对接
- 鸿蒙分布式同步仅在相同华为账号登录的设备间生效
- 系统允许后台持续监听剪贴板变化（需申请对应权限）
- 图片类型的剪贴板内容上限为 10MB，超出部分不捕获并提示用户
- 用户数据存储合规性遵循当地数据保护法规，由后端服务保证
- 验证码有效期为 5 分钟，登录态（Token）有效期为 30 天
