# Feature Specification: 剪贴板条目详情页

**Feature Branch**: `002-entry-detail-page`  
**Created**: 2026-04-08  
**Status**: Draft  
**Input**: User description: "加个详情页，文本类的可以编辑修改，其他的可以预览内容"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看文本内容详情并编辑 (Priority: P1)

用户在历史或收藏列表中点击一条文本类型的剪贴板记录，进入详情页查看完整内容。用户可以直接在详情页中编辑文本，修改后保存覆盖原内容。

**Why this priority**: 文本是剪贴板最常见的内容类型，查看和编辑是核心需求，提供最直接的用户价值。

**Independent Test**: 复制一段文本 → 在历史列表点击该条目 → 进入详情页看到完整文本 → 修改文本 → 点击保存 → 返回列表确认内容已更新。

**Acceptance Scenarios**:

1. **Given** 历史列表中存在一条文本记录，**When** 用户点击该条目，**Then** 进入详情页显示完整文本内容，文本可编辑
2. **Given** 详情页中已打开一条文本记录，**When** 用户修改文本内容并点击保存，**Then** 内容更新成功，提示保存成功，返回列表后显示更新后的内容
3. **Given** 详情页中已打开一条文本记录，**When** 用户修改文本后未保存直接返回，**Then** 弹出确认对话框询问是否放弃修改
4. **Given** 详情页中已打开一条文本记录，**When** 用户点击复制按钮，**Then** 将完整文本复制到系统剪贴板，提示复制成功

---

### User Story 2 - 预览非文本内容 (Priority: P2)

用户点击图片类型的剪贴板记录，进入详情页查看图片预览。用户可以查看图片的元信息（来源应用、复制时间等）。

**Why this priority**: 图片是第二常见的内容类型，预览功能增强用户体验但非核心。

**Independent Test**: 复制一张图片 → 在历史列表点击该条目 → 进入详情页看到图片预览和元信息。

**Acceptance Scenarios**:

1. **Given** 历史列表中存在一条图片记录，**When** 用户点击该条目，**Then** 进入详情页显示图片预览
2. **Given** 图片详情页已打开，**When** 用户查看详情页，**Then** 显示来源应用、复制时间等元信息

---

### User Story 3 - 管理条目操作 (Priority: P3)

用户在详情页中可以对当前条目执行管理操作：收藏/取消收藏、删除、复制内容。

**Why this priority**: 管理操作增强便利性，但用户也可在列表页完成这些操作。

**Independent Test**: 进入任意条目详情页 → 点击收藏按钮 → 确认收藏状态变更 → 点击删除 → 确认条目被删除。

**Acceptance Scenarios**:

1. **Given** 详情页已打开一条未收藏的条目，**When** 用户点击收藏按钮，**Then** 条目标记为已收藏，按钮状态更新
2. **Given** 详情页已打开一条条目，**When** 用户点击删除按钮并确认，**Then** 条目被删除，返回列表页，该条目不再显示
3. **Given** 详情页已打开一条文本条目，**When** 用户点击复制按钮，**Then** 内容复制到系统剪贴板，提示复制成功

---

### Edge Cases

- 超长文本内容在详情页支持滚动浏览全部内容
- 编辑后内容为空时，保存按钮应禁用或提示"内容不能为空"
- 条目在详情页打开期间被外部删除（如通过清除所有数据），返回时应处理数据不一致
- 图片内容暂时只显示占位符"[Image]"，未来版本支持真正图片预览

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供剪贴板条目详情页，用户从历史或收藏列表点击条目后进入
- **FR-002**: 详情页必须显示条目的完整内容（文本显示可编辑区域，图片显示预览）
- **FR-003**: 用户必须在详情页中直接编辑文本类型条目的内容
- **FR-004**: 编辑文本后，用户必须能保存修改，更新后的内容覆盖原条目
- **FR-005**: 未保存修改就返回时，系统必须提示用户确认是否放弃修改
- **FR-006**: 详情页必须显示条目的元信息：来源应用、内容类型、创建时间
- **FR-007**: 详情页必须提供复制内容到系统剪贴板的功能
- **FR-008**: 详情页必须提供收藏/取消收藏的切换功能
- **FR-009**: 详情页必须提供删除条目功能，删除前需用户确认
- **FR-010**: 编辑保存后，历史列表和收藏列表必须同步刷新

### Key Entities

- **ClipboardEntry（已有）**: 复用现有数据模型，详情页展示其所有字段。关键字段包括：完整内容、内容类型、来源应用、创建时间、是否收藏。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以在 2 步内从列表进入详情页并看到完整内容
- **SC-002**: 用户编辑并保存文本内容后，修改在 1 秒内生效
- **SC-003**: 90% 的用户无需引导即可完成"查看 → 编辑 → 保存"操作
- **SC-004**: 详情页所有操作（复制、收藏、删除）均可一键完成

## Assumptions

- 详情页从历史页和收藏页均可进入，交互方式一致（点击条目）
- 文本编辑为纯文本编辑，不支持富文本格式
- 图片类型在 v1 仅显示占位信息和元信息，不提供编辑功能
- 编辑保存后内容需要重新加密存储
- 保存操作直接覆盖原条目内容，不创建新条目
- 使用现有的 ClipboardRepository 进行数据操作，不需要新建数据表
- 详情页作为独立页面存在，使用页面导航进入（非弹窗）
